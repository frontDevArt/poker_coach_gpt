## Что вынести автору, а не решать самостоятельно

Четыре вопроса перечислены в разделе 4 handoff-файла. Два из них тяжёлые и оба про модель:

- **ICM не масштабируется на реальные лесенки выплат.** Перебор Malmuth-Harville при пятнадцати
  узлах поля переносит максимум шесть оплачиваемых мест, реальный турнир платит 165. Сейчас такой
  вход честно отвергается гардом `MAX_ICM_PREFIXES`, то есть `analyze` не считает ICM ровно для
  того случая, ради которого писался. Это предмет отдельного плана, а не круга правок.
- **Соперник в олл-ине (стек 0 BB) разбору не поддаётся.**

Не изобретать ответы на них внутри задачи. Если по ходу ревью кто-то предложит «просто исключить
нулевые стеки» или «просто ограничить глубину» — это смена модели, меняющая каждое ICM-число,
которое печатает коуч.

## Метод и конвенции

- Subagent-driven development: свежий исполнитель на задачу, затем **два** ревью — сначала
  соответствие спеке, потом качество кода. Правки ревью отдельными `fix(engine): …`.
- Тесты — аналитические инварианты, проверяемые на бумаге. Константа вроде `0.4412` в тесте
  означает, что тест написан неправильно.
- **В каждый тест на отказ — различающий `match=`.** В этих модулях гарды взаимно затеняются:
  снесёшь один, отказ придёт от следующего по ходу, и голый `pytest.raises(ValueError)` останется
  зелёным. Пин проверять грепом по соседним сообщениям.
- **Мутировать оператор — не то же, что снести ветку.** Класс «снести гард целиком» обязателен.
  За этот план он вскрывал переживших мутантов трижды, и каждый раз таблица исполнителя
  рапортовала «0 выживших»: она описывала придуманные мутации, а не перечень точек отказа в коде.
- Имя, передаваемое в `_checks.py`, обязано быть существительным мужского рода — шаблоны собраны
  как `{name} должен быть > 0`.
- Если план требует аналитически ложного или противоречит собственным Global Constraints — не
  выполнять дословно, проверить и записать решение против плана в журнал. За два плана так сделано
  больше двадцати раз.

## Ловушки окружения

- **Не запускать `python` со скриптом из `packages/poker-engine/src/poker_engine`**: лежащий там
  `types.py` затеняет стандартный модуль `types`, интерпретатор не стартует вообще. Запускать из
  `packages/poker-engine` или из корня репозитория.
- **`pyproject.toml` уже держит `addopts = "-q"`.** Свой дополнительный `-q` даёт `-qq` и глушит
  итоговую строку `N passed`. Полный прогон гонять без своего `-q`.
- **Полный прогон ~8 минут** (282 теста, 498 с). Запускать синхронно, таймаут 600000 мс. Фоновый
  прогон не переживает обрыв сессии — проверено дважды.
- **Мутационный прогон — единственным процессом.** Наложение двух экземпляров скрипта уже портило
  рабочий файл. Сбрасывать `__pycache__`, запускать `-B -p no:cacheprovider`, откат сверять `diff`
  с эталонной копией.
