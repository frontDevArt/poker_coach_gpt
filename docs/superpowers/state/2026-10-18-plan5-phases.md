## 1. Правила каждой фазы

Действуют §1.1–§1.7 документа фаз плана 3 (`2026-09-24-plan3-phases.md`) **дословно**, с
заменами плана 4 и этими:

| Там | Здесь |
|---|---|
| журнал плана 4 | `docs/superpowers/state/2026-10-18-plan5-execution-notes.md` (создаёт Фаза 1) |
| промпт `plan4-next-prompt.md` | `docs/superpowers/state/plan5-next-prompt.md` |
| реестр долгов §5 плана 4 | реестр §5 этого документа |
| сьют ~8 с | сьют ~50–56 с на входе, ~93 с после Фазы 1 (сетка сверки D27 ~60 с): `addopts` уже `-q`, запускать без `-q`; при отладке — только свой файл |
| большие файлы, которые не читать целиком | `allin_matrix.json` (не читать вообще); план 5 целиком — читать Global Constraints, Review Focus, Задачу своей фазы и Задачу, которую ревьюишь; спеку — разделы, названные в задаче |

Остальное без изменений: ревью делает следующая фаза; чекпоинт между ревью и реализацией
(больше пяти находок или больше одного коммита починки — реализацию не начинать, задача уходит
в фазу `kb`); мутанты руками по одному, откат `git checkout -- <файл>`, с
`PYTHONDONTWRITEBYTECODE=1` и чисткой `__pycache__`; итог ревью — список находок или ровно
`НАХОДОК НЕТ`, в журнал **до** починки; одна починка — один `fix(engine): …`; решения против
плана — блоком «Решения по находкам ревью (Фаза N, дата)» в тексте задачи.
