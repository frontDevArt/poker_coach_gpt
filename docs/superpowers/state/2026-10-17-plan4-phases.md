# План 4 по фазам: одна фаза — одна сессия

План: `docs/superpowers/plans/2026-10-17-pushfold-advisor.md`. Спека:
`docs/superpowers/specs/2026-10-17-pushfold-advisor-design.md`. Решение пользователя
(2026-10-17): резать по правилам плана 3, `docs/superpowers/state/2026-09-24-plan3-phases.md`.

Фазы идут **строго по порядку**. Каждая сессия заканчивается отчётом и промптом следующей фазы.
Последняя фаза выдаёт промпт плана 5.

---

## 1. Правила каждой фазы

Действуют §1.1–§1.7 документа фаз плана 3 **дословно**, с заменами:

| Там | Здесь |
|---|---|
| журнал `2026-09-12-icm-field-execution-notes.md` | журнал `docs/superpowers/state/2026-10-17-pushfold-execution-notes.md` (создаёт Фаза 1) |
| промпт `plan3-next-prompt.md` | `docs/superpowers/state/plan4-next-prompt.md` |
| реестр долгов §5 того документа | реестр §5 этого документа |
| «не больше трёх полных прогонов за фазу» | снято: сьют идёт ~8 с, гонять сколько нужно, всегда `-q` |
| большие файлы, которые не читать целиком | те же плюс `allin_matrix.json` (не читать вообще, только через модуль) и план 4 целиком: читать Global Constraints, Review Focus, Задачу своей фазы и Задачу, которую ревьюишь |

Остальное без изменений: ревью делает следующая фаза; чекпоинт между ревью и реализацией (больше
пяти находок или больше одного коммита починки — реализацию не начинать, задача уходит в фазу
`kb`); мутанты руками по одному, откат `git checkout -- <файл>`, с
`PYTHONDONTWRITEBYTECODE=1` и чисткой `__pycache__` (D22 плана 3); итог ревью — список находок
или ровно `НАХОДОК НЕТ`, в журнал **до** починки; одна починка — один `fix(engine): …`;
решения против плана — блоком «Решения по находкам ревью (Фаза N, дата)» в тексте задачи.
