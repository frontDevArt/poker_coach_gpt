# MVP префлоп-тренера: модель колла (D30), лимп SB, порог push/fold, конвейер тренера — план имплементации

> **Исполняется по фазам:** `docs/superpowers/state/2026-10-21-plan6-phases.md`. Одна фаза —
> одна сессия до ~150k контекста. Промпт очередной фазы лежит в
> `docs/superpowers/state/plan6-next-prompt.md`.

> **Режим исполнения — решение пользователя, перекрывает рекомендацию скиллов.**
> Субагенты не используются. Каждая задача исполняется **линейно** на Opus. Задачу,
> реализованную в фазе k, ревьюит фаза k+1. Находки ревью чинятся отдельными коммитами, и
> цикл «ревью → починка → ревью» идёт, пока ревью не ответит `НАХОДОК НЕТ`. Шаги помечены
> `- [ ]` для отметок.

**Goal:** серия скриншотов одной раздачи → пошаговый разбор префлопа с историей: на каждый кадр —
действие с размером и «почему» только числами движка, проверенными линтером; советы `open` и
`vs_open` — в полосе публичных чартов MTT (D30 закрыт), `SB` с лимпом, порог push/fold по
правилу (D28); диапазоны по линии живут в состоянии раздачи и переходят на флоп.

**Architecture:** сначала модель колла: колл открытия только у закрывающего действие, колл без
олл-ина — терминал реализации эквити по SPR с параметрами, подобранными по публичным чартам (T2),
лимп героя с `SB`, бюджет, порог push/fold. Затем конвейер: файл раздачи как единственное
состояние сессии и команда `coach`, тип `Hand` и протокол советника с `explain`, итог улицы
префлопа с диапазонами на флоп, факты объяснения с готовой печатью, линтер чисел, скиллы L6/L7.

**Tech Stack:** Python 3.12+, pytest, `numpy`; солвер CFR+ `preflop_solver` и дерево
`preflop_tree` плана 5; `allin_matrix`, `nash`, `icm_field` планов 3–4.

**Spec:** `docs/superpowers/specs/2026-10-21-preflop-call-model-design.md` (Задачи 1–5) и
`docs/superpowers/specs/2026-10-21-preflop-trainer-design.md` (Задачи 6–10).

## Global Constraints

Из спек и конвенций ядра (`CLAUDE.md`); требования каждой задачи включают этот раздел.

- **Один коммит на задачу,** правки ревью — отдельными `fix(engine): …`. Вынос общего кода и смена
  протокола — отдельным `refactor(engine): …` до `feat` своей задачи; ускорение — `perf(engine)`.
- **Валидация живёт в движке, не в CLI.** Тексты `ValueError` и отказов — пользовательские
  сообщения; существующие не меняются. Смены контракта — **только** списки спеки модели колла §11
  и спеки тренера §13.
- **Общие гарды — только из `_checks.py`.** Имя для гарда — существительное мужского или
  среднего рода.
- **Тест на отказ пинит сообщение через `match=`.** Мутационная приёмка включает класс
  «снести гард целиком».
- **Тесты — аналитические инварианты.** Внешние числа — только из `tests/data/mtt_reference.json`
  (источники спеки модели колла §2.1, с адресами) и HU-чарт плана 4. Чисел из памяти модели нет.
- **Прототип — независимая проверка.** Числа R1–R3 спеки модели колла получены копией
  дерева и солвера; реализация обязана повторить их на тех же точках и константах в пределах
  ±1 п.п. (Задачи 1–2, до подбора). Расхождение больше — находка в своей задаче, а не повод
  подогнать эталон.
- **Пометка ставится, только когда она правда.** **Ключи ответа — camelCase.**
- **Ничего не зашивать про стол:** размер стола — число мест, анте — из банка, поле `blinds` не
  читается советниками (только переводом единиц кадра, Задача 6).
- **`analyze.py`, `nash.py`, `pushfold_game.py` по смыслу не меняются,** кроме: новых проверок
  валидатора (Задача 6) и константы `PUSHFOLD_MAX_BB` (Задача 5).
- **Прогон тестов:** `cd packages/poker-engine && .venv/bin/python -m pytest` (Windows —
  `.venv/Scripts/python`). До начала работ: **1100 passed**, ~106–122 с в облаке. В облаке нет
  `.venv` — поставить по «Командам» `CLAUDE.md`.
- **Бюджеты** — спека модели колла §9: 6-max ≤ 2 с, 9-max ≤ 4 с (или 6 с по правилу Задачи 5) на
  `open` `UTG` 25 BB, машина пользователя; облако быстрее ~1.5 раза. **Решение пользователя
  (Фаза 3c, 2026-10-21):** 6-max ≤ 4 с, 9-max ≤ 8 с на его машине — она медленнее облака в ~1.85
  раза (Задача 3, блок «Фаза 3c»).

## Review Focus

Входы, которые спеки подразумевают, но ни один их инвариант не называет. Тест — в задаче-владельце.

1. **Колл 3-бета, после которого за банком 0.1 BB** (сыгранный размер почти на весь стек).
   Ожидание: терминал реализации с `SPR ≈ 0`, `p` в пределах `1e-6` от `e`, без `nan`. Задача 2.
2. **Пара классов с весом 0** (несовместимые по картам, эквити в таблице 0 или 1). Ожидание:
   матрица `p` конечна, зажим `[1e-9, 1 − 1e-9]` до логита. Задача 2.
3. **Стек `SB` не больше 1 BB с вложенным** (лимп — на весь стек). Ожидание: лимп сливается с
   олл-ином, у `SB` `fold` и `allin`, узла с отрицательным стеком нет. Задача 4.
4. **Кадр в фишках с нецелым делением** (`blinds.bb = 1400`, стек 30333). Ожидание: BB без
   округления, валидатор проходит в своём допуске. Задача 6.
5. **Первый кадр раздачи — флоп** (пользователь не снял префлоп). Ожидание: шаг-отказ советников,
   `streets.preflop.reason` «нет кадров префлопа», без исключения. Задача 7.
6. **`undo` кадра, закрывшего улицу.** Ожидание: итог улицы снят вместе с кадром, файл равен
   файлу до шага. Задачи 6–7.
7. **Число внутри текста отказа** («место 3 уже в олл-ине…»). Ожидание: факт-причина несёт его в
   `display`, линтер его пропускает. Задача 8.
