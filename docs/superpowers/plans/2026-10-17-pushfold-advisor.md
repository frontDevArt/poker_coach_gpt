# Советник push/fold: Nash с ICM-поправкой — план имплементации

> **Исполняется по фазам:** `docs/superpowers/state/2026-10-17-plan4-phases.md`. Одна фаза —
> одна сессия до ~150k контекста. Промпт очередной фазы лежит в
> `docs/superpowers/state/plan4-next-prompt.md`.

> **Режим исполнения — решение пользователя, перекрывает рекомендацию скиллов.**
> Субагенты не используются. Каждая задача исполняется **линейно** на Opus. Задачу,
> реализованную в фазе k, ревьюит фаза k+1. Находки ревью чинятся отдельными коммитами, и
> цикл «ревью → починка → ревью» идёт, пока ревью не ответит `НАХОДОК НЕТ`. Шаги помечены
> `- [ ]` для отметок.

**Goal:** советник отвечает на префлоп-спот короткого стека действием с размером («олл-ин
9.4 BB», «колл 7.2 BB», «фолд») и фактами для объяснения: EV по ICM и по фишкам, равновесные
диапазоны, вклад голов PKO.

**Architecture:** таблица эквити олл-ина «класс против класса» генерируется движком один раз и
лежит в `data/`. Узел скриншота превращается в подыгру push/fold: открывающий и отвечающие по
порядку хода, исходы и выплаты по фишкам и по ICM модели поля. Солвер на `numpy` ищет
равновесие fictitious play; советник берёт лучший ответ конкретной руки героя против
равновесия соперников. Советник встаёт в реестр за общим интерфейсом, точка входа —
`advise` и одноимённая подкоманда CLI.

**Tech Stack:** Python 3.12 (`.venv` пользователя — 3.12.3), pytest, `numpy` (новая
зависимость), `phevaluator 0.6.0` (генерация таблицы), модель ICM `icm_field` плана 3.

**Spec:** `docs/superpowers/specs/2026-10-17-pushfold-advisor-design.md` (утверждена
2026-10-17 вместе с решениями §12).

## Global Constraints

Из спеки и конвенций ядра (`CLAUDE.md`); требования каждой задачи включают этот раздел.

- **Один коммит на задачу,** правки ревью — отдельными `fix(engine): …`. Исключение —
  Задача 2: перенос поиска стека поля идёт отдельным `refactor(engine): …` до `feat`
  (спека §10: общий код выносится отдельным рефакторингом, не попутно).
- **Валидация живёт в движке, не в CLI.** Тексты `ValueError` и тексты отказов советника —
  пользовательские сообщения. Существующие тексты не меняются.
- **Общие гарды — только из `_checks.py`.** Имя для гарда — существительное мужского или
  среднего рода (`{name} должен быть > 0`, `{name} не может быть отрицательным`).
- **Тест на отказ пинит сообщение через `match=`.** Мутационная приёмка включает класс
  «снести гард целиком».
- **Тесты — аналитические инварианты.** Чисел из памяти модели нет. Единственное внешнее
  число — эталонный HU-чарт (Задача 3), заносится из источника со ссылкой в файле данных.
- **Пометка ставится, только когда она правда** (правило `analyze`).
- **Ключи ответа `advise` — camelCase,** как у `analyze`: контракт с приложением на TypeScript.
- **Ничего не зашивать про стол:** размер стола — число мест на скриншоте, анте — из банка.
  Поле `blinds` узла советник не читает.
- **`analyze.py`, `icm_field.py`, `bounty.py` по смыслу не меняются.** Единственная правка
  `analyze.py` — вызов перенесённой функции стека поля (Задача 2, рефакторинг без смены
  поведения).
- **Прогон тестов:** `cd packages/poker-engine && .venv/Scripts/python -m pytest -q` (Linux —
  `.venv/bin/python`). До начала работ: **477 passed**, ~8 с.
- **Приёмка плана:** `advise` на эталонном споте укладывается в 2 секунды (Задача 5), HU
  push/fold по фишкам совпадает с опубликованным чартом (Задача 3).

## Review Focus

Входы, которые спека подразумевает, но ни один её инвариант не называет. Тест на каждый
стоит в задаче-владельце.

1. **Банк меньше суммы вложений** — распознавание дало `potBb` меньше Σ `investedBb`. Ожидание:
   расхождение в пределах округления (`0.1 BB` на место) обнуляет мёртвые деньги, большее —
   `ValueError` с текстом. Тест — Задача 2.
2. **Большой блайнд в олл-ине с блайнда** (стек 0, вложено ≤ 1 BB) среди отвечающих. Ожидание:
   отказ с причиной, а не деление на ноль в ICM. Тест — Задача 2.
3. **Место со стеком 0 вне раздачи** (выбывший ещё на скриншоте). Ожидание: отказ с причиной,
   а не `ValueError` из `icm_field`. Тест — Задача 2.
4. **Все сфолдили до большого блайнда, герой — BB.** Решения нет. Ожидание: отказ, а не
   совет «олл-ин» в пустой банк. Тест — Задача 2.
5. **Олл-ин не больше вложенного героем** в `facing_allin`: `SB` пошёл олл-ин на 0.8 BB,
   герой — `BB` с 1.0 BB в банке. Колла нет, совет `call` с размером 0 бессмыслен. Ожидание:
   отказ «к коллу ничего», а не совет. Тест — Задача 2.

## Задача 2: подыгра push/fold из узла скриншота

**Files:**
- Modify: `src/poker_engine/icm_field.py` (+ `field_stack`), `src/poker_engine/analyze.py`
  (вызов вместо `_field_stack`, только рефакторинг)
- Create: `src/poker_engine/pushfold_game.py`
- Modify: `tests/conftest.py` (фикстуры споток)
- Test: `tests/test_pushfold_game.py`

**Interfaces:**
- Consumes: `handstate` (`TournamentContext`, `DecisionNode`, `assign_positions`),
  `types.positions_for`, `icm_field.table_equities`, `bounty.knockout_cash`,
  `TournamentContext.ladder()/protected_ladder()`, `handstate.ROUNDING_STEP_BB`.
- Produces:
  - `icm_field.field_stack(players_left: int, average_stack_bb: float | None, table: list[float], field_count: int) -> float`
    — тело и оба текста `analyze._field_stack` дословно;
  - `pushfold_game.PUSHFOLD_MAX_BB = 12.0`;
  - `pushfold_game.Spot` — `frozen dataclass`:
    `kind: str` (`"first_in"` | `"facing_allin"`), `players: list[Seat]` — участники подыгры
    в порядке хода, `[0]` — открывающий; `hero_at: int` — индекс героя в `players`;
    `totals: list[float]` — `stackBb + investedBb` каждого участника; `dead_bb: float` — банк
    минус вложения участников; `bystanders: list[Seat]` — остальные места стола;
  - `pushfold_game.read_spot(node: DecisionNode) -> Spot | str` — спот или причина отказа;
  - `pushfold_game.Outcomes` — `frozen dataclass` с массивами выплат по участникам:
    `steal: list[float]` (все сфолдили, банк открывающему), `walk: list[float]` (открывающий
    сфолдил, банк большому блайнду), `win: list[list[float]]` и `lose: list[list[float]]` —
    по одному ряду на отвечающего: `win[k]` — открывающий выиграл олл-ин против
    `players[k + 1]`, `lose[k]` — проиграл. Каждый ряд — выплаты всем участникам в порядке
    `players`;
  - `pushfold_game.outcome_stacks(spot: Spot) -> dict[str, …]` — стеки всех мест стола по
    каждому исходу (ключи `steal`, `walk`, `win`, `lose`), выбывший — `0.0`;
  - `pushfold_game.chip_outcomes(spot: Spot) -> Outcomes` — выплата = стек после раздачи, BB;
  - `pushfold_game.icm_outcomes(spot: Spot, node: DecisionNode, context: TournamentContext, bounties: bool) -> Outcomes`
    — эквити в долларах на модели поля, плюс наличные за голову победителю нокаута при
    `bounties=True`.

**Распознавание спота.** Порядок хода префлопа — `positions_for(len(seats))`, места
сопоставляются через `assign_positions`. «Блайнды» — места на позициях `SB` и `BB`.

- `first_in`: все до героя по порядку хода сфолдили (`inHand = False`); каждое место, кроме
  блайндов, вложило 0; `SB` вложил строго меньше 1 BB; `BB` — не больше 1 BB. Открывающий —
  герой, отвечающие — все в раздаче после него.
- `facing_allin`: до героя по порядку хода в раздаче ровно одно место, и у него
  `stackBb == 0` — олл-инщик; все остальные до героя сфолдили; после героя все вложили 0,
  кроме блайндов (те же условия, что выше). Открывающий — олл-инщик, отвечающие — все в
  раздаче после него, включая героя.

Порядок проверок — порядок таблицы ниже: первая сработавшая причина и есть ответ. Место до
героя в раздаче со стеком больше 0 — «банк открыт не олл-ином»; два и больше мест до героя в
раздаче, хоть одно со стеком 0, — «олл-инов больше одного».

Причины отказа — тексты пользователя, пинятся тестами дословно:

| Условие | Текст |
|---|---|
| улица не префлоп | `push/fold советует только на префлопе` |
| у героя стек 0 | `герой уже в олл-ине: решения нет` |
| герой — BB, перед ним только фолды | `все сфолдили до большого блайнда: решения нет` |
| лимп или рейз не в олл-ин перед героем | `банк открыт не олл-ином: это не спот push/fold` |
| больше одного олл-ина | `олл-инов перед героем больше одного: мультипот вне модели` |
| олл-инщик вложил не больше, чем герой | `к коллу ничего: олл-ин не больше вложенного героем` |
| у отвечающего стек 0 | `место {seatIndex} уже в олл-ине с блайнда: вне модели` |
| у места вне раздачи стек 0 | `на месте {seatIndex} стек 0 вне раздачи: ICM не определён` |
| `first_in`, эффективный стек > порога | `эффективный стек {x:.1f} BB выше порога push/fold {PUSHFOLD_MAX_BB:.0f} BB` |

Эффективный стек `first_in` — `min(total героя, max(total отвечающих))`.

**Мёртвые деньги.** `dead_bb = potBb − Σ investedBb всех мест` (анте и вложения сфолдивших).
Отрицательное в пределах `ROUNDING_STEP_BB × число мест` обнуляется; глубже —
`ValueError("банк меньше суммы вложений мест: {pot:.1f} BB против {invested:.1f} BB")`.

**Исход олл-ина открывающего `o` против отвечающего `j`.** Каждый ставит
`stake = min(total_o, total_j)`; победитель получает `dead + Σ вложений остальных участников +
2·stake`, излишек больше `stake` возвращается владельцу; стек проигравшего — `total − stake`,
выбыл, если 0. Остальные участники теряют своё вложенное, их стек — `stackBb`. `steal` —
открывающему всё, что в банке, плюс свой `total`. `walk` — то же для `BB`. Посторонние места
(`bystanders`) не меняются ни в одном исходе.

**ICM исхода.** Стол — стеки всех мест после исхода без выбывшего; `field_count =
node.playersLeft − число мест на скриншоте` (не меняется); `field_stack` — `icm_field.field_stack`
по стекам **до** раздачи, как в `analyze` (смещение — долг D23). Лесенка — `protected_ladder`,
если она не `None`, иначе `ladder()`. Выбывшему — `ladder.prize(node.playersLeft)`.
`table_equities` зовётся по одному разу на исход: `2m + 2` вызова на подыгру с `m`
отвечающими.

**Головы.** При `bounties=True` в исходе с выбыванием победитель получает сверх ICM
`knockout_cash(ценник выбывшего)`. Без ценников `bounty.py` не вызывается.

**Модель EV** (спека §5.1–5.4). Классы — строки/столбцы таблицы `e`, `w`. Индекс игрока: 0 —
открывающий, `1..m` — отвечающие. Блокеры — только попарные. В формулах `win[j]` — ряд
отвечающего `j`, в коде это `outcomes.win[j − 1]`; второй индекс — получатель выплаты.

Для класса открывающего `h`: `q_i(h) = Σ_x call_i[x]·w[h,x] / Σ_x w[h,x]` — вероятность колла
`i`; `a_i(h) = Σ_x call_i[x]·w[h,x]·e[h,x] / Σ_x w[h,x]` — колла и победы открывающего.

```
reach_j(h) = Π_{i<j} (1 − q_i(h))
EV_push_0(h) = reach_{m+1}(h)·steal[0]
             + Σ_j reach_j(h)·(a_j(h)·win[j][0] + (q_j(h) − a_j(h))·lose[j][0])
EV_fold_0    = walk[0]
```

Для отвечающего `j` с классом `x`: распределение класса открывающего
`p(h | x) ∝ push[h]·w[h,x]`. Отвечающие между открывающим и `j` в этой модели сфолдили —
их фолд на `p` не влияет (только попарные блокеры).

```
EV_call_j(x) = Σ_h p(h|x)·(e[h,x]·win[j][j] + (1 − e[h,x])·lose[j][j])
EV_fold_j(x) = Σ_h p(h|x)·( reach'_{m+1}(h)·steal[j]
             + Σ_{k>j} reach'_k(h)·(a_k(h)·win[k][j] + (q_k(h) − a_k(h))·lose[k][j]) )
reach'_k(h) = Π_{j<i<k} (1 − q_i(h))
```

Fictitious play: на шаге `t` каждый игрок берёт чистый лучший ответ на текущие средние
стратегии остальных, средние обновляются `σ ← σ + (BR − σ)/(t + 2)`. Начальные стратегии —
все частоты 0.5. При равенстве EV лучший ответ — фолд (детерминизм). Эксплуатируемость —
максимум по игрокам выигрыша `Σ_x prior(x)·(max EV(x) − EV_σ(x))`, `prior(x) =
combos_of(x)/1326`; проверяется каждые 10 итераций, остановка при `≤ eps`.

  объяснения;
- `sizeBb` — `total` героя в `first_in`; в `facing_allin` — `min(total олл-инщика, total
  героя) − investedBb героя`. При `fold` ключа `sizeBb` нет;
- `nash` — `{"icm": {"exploitabilityUsd", "iterations"}, "chip": {"exploitabilityBb",
  "iterations"}}`: решений два, у каждого свои единицы;
- `ranges.opponents` — все участники подыгры, кроме героя, по порядку хода: открывающий —
  `role: "shover"`, отвечающие — `"caller"`;
- `effectiveStackBb` — эффективный стек спота (Задача 2).

**EV руки героя** (спека §5.7). Строка весов — `hand_weights(hero_cards)`; строка эквити —
ряд `equity_matrix()` класса героя. Эквити внутри пары классов — среднее по классу, блокеры —
от точной комбинации (решение плана: таблица «комбинация против класса» не строится).
Герой-открывающий — `opener_ev`, герой-отвечающий — `responder_ev`.

**Вклад голов.** При `pko` ICM-равновесие решается с `icm_outcomes(..., bounties=True)`;
`ev.bountyUsd` — `marginUsd` с головами минус `marginUsd` на `icm_outcomes(..., bounties=False)`
при тех же стратегиях соперников (равновесие не перерешивается).

**Пометки** (спека §8): `mh_bias` — всегда; `field_homogeneous` — при поле > 0; `pko`,
`bubble_protection`, `ladder_incomplete`, `late_reg_open` — по тем же условиям, что в `analyze`;
`no_overcall` — `m > 1`; `fold_as_walk` — после открывающего есть кто-то, кроме `BB`;
`close_spot` — `|marginUsd| ≤ eps` ICM-решения; `nash_not_converged` — хоть одно решение не
сошлось.

**Против текста спеки, записать в решения:** `fold_as_walk` ставится и в `facing_allin`,
