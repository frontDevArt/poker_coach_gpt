# poker-engine

Вычислительное ядро покерного коуча. Единственный источник чисел для скиллов
из `.claude/skills/` и для Nuxt-приложения.

## Установка

```bash
python -m venv .venv
.venv/Scripts/python.exe -m pip install -r requirements-dev.lock
.venv/Scripts/python.exe -m pip install -e ".[dev]" --no-deps
```

`requirements-dev.lock` пинит версии зависимостей разработки; `--no-deps` во второй
команде не даёт pip разъехаться с этими пинами.

Силу руки оценивает `phevaluator` (C-расширение без рантайм-зависимостей; `pokerkit`
остаётся эталоном в тестах). У `phevaluator 0.6.0` есть колёса для Windows на Python 3.13 и
3.14 и исходный архив, так что `.venv` годится от любого Python 3.11+. Прежний оценщик
`eval7` не ставился на Windows с Python 3.13+ и заменён.

## Тесты

```bash
.venv/Scripts/python.exe -m pytest -v
```

## Использование

```bash
.venv/Scripts/poker-engine.exe icm --stacks 75,25 --payouts 70,30
```

Все команды печатают одну строку JSON. При ошибке — `{"error": "..."}` и код возврата 1.
Полный список команд — в `.claude/skills/poker-math/SKILL.md`.

### Команды

| Команда | Для кого | Заметки |
|---|---|---|
| `analyze` | приложение | Разбор состояния со скриншота: ICM, пот-оддсы, PKO |
| `advise` | приложение, скилл `poker-preflop-mtt` | Совет на последнем узле раздачи: действие с размером и почему (push/fold) |
| `icm`, `risk-premium` | скиллы, отладка | ICM-эквити, risk premium и bubble factor. Считают только переданные стеки, без поля: верны, когда `--stacks` — весь оставшийся турнир (финальный стол). В середине турнира числа ICM брать из `analyze` (модель «стол + поле») |
| `potodds`, `bounty-ev` | скиллы, отладка | Порог эквити, с головой PKO и без |
| `equity` | скиллы, отладка | Либо `--hands`, либо `--hero` вместе с `--vs-range` |

`equity` работает в одной из двух форм и не смешивает их: `--hands AhKh,AdKd` считает
эквити двух конкретных рук друг против друга, `--hero JhTh --vs-range TT+` — руки героя
против диапазона соперника. `--hands` вместе с `--vs-range` отвергается.

`bounty-ev --bounty` — число, показанное над игроком на экране; оно и есть наличные за нокаут.
Пополам его не делить: половиной полного баунти оно уже является (внёс $3.00 — показано
$1.50), а собственный ценник выбившего растёт на половину взятого. Флаг `--split` убран
намеренно: правильного значения у доли нет, она следует из того, что показано на экране, и
`bounty-ev … --split 0.5` теперь отвечает ошибкой `unrecognized arguments`.

### `analyze` — сквозной разбор состояния со скриншота

```bash
.venv/Scripts/poker-engine.exe analyze --input hand.json
cat hand.json | .venv/Scripts/poker-engine.exe analyze --input -
```

Вход — JSON с ключами `context` (турнирный контекст) и `nodes` (список узлов решения,
по одному на скриншот; разбирается последний, остальные нужны валидатору как история).
Ответ содержит только то, что посчитано: ключи, которых посчитать нельзя, отсутствуют,
а не заполняются нулями. Список `flags` — часть ответа, а не сноска: он перечисляет всё,
что расчётом не является (`mh_bias`, `field_homogeneous`, `ladder_incomplete`,
`late_reg_open`, `no_pushfold`, `vpip_default`, `icm_pressure_undefined`, `pko`,
`bubble_protection`).

ICM в `analyze` считается моделью «стол поимённо + однородное поле» (`icm_field`): места за
столом различимы, остальные `nodes[-1].playersLeft − мест за столом` игроков поля неразличимы
и держат средний стек турнира за вычетом стола. Место героя — настоящее место в турнире, и
приз берётся из лесенки по нему целиком, без обрезания. Стоимость — `2^t × (F+1)` состояний:
экспонента только от стола (не больше десяти мест), поле входит линейно. `icm.heroEquity`
сопровождается `icm.playersLeft` и `icm.tableSeats`.

`field_homogeneous` ставится, когда поле вне стола есть: разброс стеков поля модель не видит.
На финальном столе поля нет, и пометки тоже.

`ladder_incomplete` означает, что интервалы выплат покрывают меньше мест, чем `placesPaid`:
призы за непокрытые места модель считает нулевыми. Это либо недоснятый скриншот лобби, либо
кривое распознавание. Пометка — про вход, а не про число: `icm.heroEquity` занижено, только
если среди непокрытых есть места не глубже `nodes[-1].playersLeft`; места глубже уже вручены
выбывшим и в расчёт не входят. Пока открыта поздняя регистрация
(`late_reg_open`), лесенка к тому же предварительна: число входов растёт, и порог числа
оплачиваемых мест может перескочить.

Поле `averageStackBb` необязательно: средний стек нужен только, чтобы населить поле вне стола.
Когда игроков в узле столько же, сколько мест за столом, поля нет, и средний стек можно не
присылать; в остальных случаях его отсутствие — отказ с текстом про средний стек.

**PKO** узнаётся по ценникам голов, а не по настройке: `seats[].bountyUsd` — число, показанное
над игроком на экране (наличные выбившему). Есть хоть один ценник — пометка `pko`; тогда ценник
обязателен у героя и у каждого, кто в раздаче, иначе отказ. При определённом сопернике ответ
получает блок `bounty`: `villainPriceUsd`, `knockoutCashUsd` (равен ценнику соперника),
`ownPriceGrowthUsd` (половина взятого), `heroPriceAtRiskUsd`, `bbValueUsd` — доллары за большой
блайнд (призы мест `1..playersLeft`, делённые на фишки стола и поля) — и при колле
`requiredEquityWithBounty`. Голова снижает порог, только если колл накрывает остаток соперника и
герой может его выбить; иначе порог равен `requiredEquity`. Блок `bounty` лежит отдельно от
`icm` и с ним не складывается. Уже взятые баунти в расчёт не входят. Колл против олл-ина до
блока не доходит — см. ограничение ниже.

**Защита на баббле** («ранняя пташка» GG): `context.bubbleRefundUsd` — бай-ин, который рум вернёт
вылетевшему на баббле. ICM учитывает его как приз за места `placesPaid + 1 .. playersLeft`: возврат
получает каждый, кто вылетел вне денег, пока живых больше, чем оплачиваемых мест, открыта ли
регистрация — не важно: `lateRegOpen` на поправку не влияет (так условие прочитано и
подтверждено пользователем; кто из живых ранняя пташка, движок не знает). Применён —
пометка `bubble_protection` и блок `bubbleProtection`: `refundUsd`, `places` (`from`/`to`) и
`riskPremiumWithoutRefund` — риск-премия и bubble factor без возврата, рядом с основными. Когда все
живые уже в деньгах или возврат нулевой, поправки нет, и ответ тот же, что без поля.
`ladder_incomplete` и `bbValueUsd` считаются по лесенке лобби: возврат платит рум, а не фонд.

Известное ограничение: раздача, где соперник уже в олл-ине (стек 0 BB), разбору не поддаётся —
`analyze` отвергает её до расчёта ICM сообщением `стек на месте N должен быть > 0`, где N —
`seatIndex` со скриншота. Как возвращать в ICM фишки, уже вложенные выбывающим, — решение о
модели, и оно пока не принято.

Ключи ответа `analyze` — camelCase (`requiredEquity`, `effectiveStackBb`), в отличие от
snake_case остальных команд (`required_equity`). Это намеренно: форма ответа `analyze` —
контракт с приложением, а ключи старых команд уже отгружены скиллам.

### `advise` — совет на последнем узле раздачи

```bash
.venv/Scripts/poker-engine.exe advise --input hand.json
cat hand.json | .venv/Scripts/poker-engine.exe advise --input -
```

Вход — тот же конверт, что у `analyze` (`context`, `nodes`, те же парсеры и проверки), плюс
необязательный `history` — список прошлых ответов `advise` по этой раздаче, по умолчанию `[]`.
Проверяется только его форма: список объектов.

Ответ даёт первый советник реестра (`advice.ADVISORS`), взявший последний узел. Советников два,
по порядку: `pushfold` (короткий стек) и `preflop` (весь остальной префлоп). Не взял никто —
ответ-отказ, а не ошибка: `{"advisor": null, "notApplicable": [{"advisor": "pushfold",
"reason": "…"}, {"advisor": "preflop", "reason": "…"}]}`. `ValueError`
(ключ `error` в CLI) остаётся для битого входа. Ключи — camelCase, как у `analyze`.

**`pushfold`** берёт префлоп-спот короткого стека двух видов: `first_in` — до героя все
сфолдили, эффективный стек (меньшее из стека героя и наибольшего стека после него, с вложенным)
не выше `PUSHFOLD_MAX_BB = 12` BB; `facing_allin` — перед героем ровно один олл-ин, остальные
сфолдили, порога нет. Остальное — отказ с причиной (рейз не в олл-ин, мультипот, постфлоп, все
сфолдили до `BB`, к коллу ничего и т. д.). Подыгра «пуш или фолд, колл или фолд» решается
дважды, по фишкам и по ICM модели поля (с головами в PKO), fictitious play на таблице эквити
«класс против класса» (`data/allin_matrix.json`). Совет — лучший ответ точной комбинации героя
против равновесия соперников по ICM:

- `action` — `allin` | `fold` в `first_in`, `call` | `fold` в `facing_allin`; активное
  действие — при `ev.icm.marginUsd > 0`;
- `sizeBb` — сколько герой ставит: весь стек с вложенным в `first_in`, в `facing_allin` —
  меньшее из олл-ина и стека героя минус уже вложенное героем; при `fold` ключа нет;
- `ev.icm` (`allinUsd`/`callUsd`, `foldUsd`, `marginUsd`) — совет; `ev.chip` (то же в BB) —
  для объяснения ICM-поправки; `ev.bountyUsd` — часть `marginUsd` от голов, только в PKO;
- `ranges.hero` — доля диапазона героя по ICM и по фишкам (`icmPct`, `chipPct`) и частота класса
  его руки (`handFreqIcm`, `handFreqChip`); `ranges.opponents` — участники подыгры по порядку
  хода (`role`: `shover` у олл-инщика, `caller` у отвечающих) с частотами по классам
  (`classes`, шаг 0.01);
- `nash` — эксплуатируемость и число итераций каждого решения (`icm` в долларах, `chip` в BB).

Пометки `advise`:

| Пометка | Что значит |
|---|---|
| `mh_bias` | ICM — Malmuth-Harville, ставится всегда |
| `field_homogeneous` | поле вне стола есть, разброс его стеков модель не видит |
| `pko` | у кого-то за столом есть ценник головы: в ICM-игре головы — наличные выбившему |
| `bubble_protection` | возврат бай-ина на баббле учтён призом за места вне денег |
| `ladder_incomplete` | лесенка покрывает меньше мест, чем `placesPaid` |
| `late_reg_open` | поздняя регистрация открыта: лесенка предварительна |
| `no_overcall` | после первого колла остальные фолдят: оверколлы не моделируются (ставится при двух и больше отвечающих) |
| `fold_as_walk` | фолд открывающего — уход банка к `BB`, хотя кто-то, кроме `BB`, ещё ответил бы (и в `facing_allin`: так моделируется фолд олл-инщика) |
| `close_spot` | EV активного действия и фолда равны с точностью допуска: рука смешанная, разница мала |
| `nash_not_converged` | предел итераций достигнут раньше допуска, диапазоны приблизительны |

Ограничения: открытие рейзом, рестил и 3-бет `pushfold` не советует — это советник `preflop`;
оверколлы не моделируются (`no_overcall`); фолд открывающего — уход банка к `BB`
(`fold_as_walk`). Олл-ин соперника на 0 BB `advise` разбирает, а `analyze` по-прежнему
отвергает (D3). Бюджет — 2 секунды на совет, тесты бюджета на 6-, 8- и 9-max `first_in`
(`tests/test_advice_budget.py`): 6-max с пятью отвечающими — ~0.2 с, 8-max с семью — ~0.5 с,
9-max с восемью — ~0.7 с. До плана 5 8-max стоил ~3 с, 9-max — ~8 с: почти всё время уходило на
ICM на чистом Python. Долг D27 закрыт планом 5: ICM модели поля на `numpy`, все `2m + 2` исходов
подыгры — один вызов `icm_field.table_equities_batch` (замер — журнал
`docs/superpowers/state/2026-10-18-plan5-execution-notes.md`, разделы «Фаза 1» и «Фаза 2»).

### Советник `preflop` — весь префлоп

Берёт узел префлопа, который не взял `pushfold`: стек любой глубины, кроме спотов push/fold.
Линия раздачи восстанавливается по кадрам (`investedBb` и `inHand` каждого узла, поле `blinds` не
читается), и по ней читается спот:

| Спот | Линия до героя | Действия героя |
|---|---|---|
| `open` | все до героя сфолдили, эффективный стек выше `PUSHFOLD_MAX_BB` | `fold`, `raise`, `allin` |
| `vs_open` | одно открытие рейзом не олл-ином, остальные сфолдили | `fold`, `call`, `raise` (3-бет), `allin` |
| `vs_3bet` | герой открыл, один 3-бет не олл-ином | `fold`, `call`, `raise` (4-бет), `allin` |
| `vs_4bet` | герой сделал 3-бет, открывший — 4-бет не олл-ином | `fold`, `call`, `allin` |
| `vs_allin_after_raise` | герой рейзил, соперник пошёл олл-ин | `fold`, `call` |
| `vs_limp` | один лимпер, остальные сфолдили | `fold` (у `BB` — `check`), `raise` (изоляция), `allin` |

Стек не выше ставки — колл на все: у такого места `fold` и `allin`. Пошаговый разбор: второй и
третий узел героя на префлопе в одной раздаче — нормальный вход (D26); дерево каждого шага
строится от начала префлопа по фактической линии, поэтому диапазоны шага N выведены из того же
равновесия, что и на шаге N−1. Состояния между вызовами нет: вход без `history` самодостаточен.

Отказы (`preflop_line.py`, `preflop_tree.py`; тексты — пользовательские, пинятся тестами):
не префлоп; герой уже в олл-ине; спот push/fold — отвечает `pushfold` (в том числе олл-ин
перед первым решением героя при любом стеке); в банк до героя вошли двое и больше —
мультипот; линия неоднозначна — нужен кадр предыдущего решения героя; все сфолдили до `BB`;
герой вошёл в банк лимпом или коллом; 5-бет не олл-ином; лимпер ответил на изоляцию рейзом не
олл-ином; место уже в олл-ине с блайнда; стек 0 вне раздачи.

**Модель.** Дерево «открывший против вошедшего»: первый вошедший после открытия закрывает
остальных (`no_overcall`), колл без олл-ина разыгрывается вскрытием без ставок по таблице эквити
(`postflop_checkdown`), олл-ин — по `data/allin_matrix.json`. Равновесие — CFR+ на `numpy`
(`preflop_solver.py`), дважды: по ICM модели поля (с головами в PKO) — совет, EV и диапазоны;
по фишкам — `evBb`. Совет — лучший ответ точной комбинации героя против равновесия соперников,
с блокерами. Лимпер не равновесен: его диапазон — профиль по бейджу VPIP
(`profiles.range_for_vpip`, без бейджа — `DEFAULT_VPIP = 25`), ответ на изоляцию внутри
диапазона решается равновесием.

**Размеры — калибровка, а не расчёт** (`preflop_tree.py`, спека плана 5, §6.2). На несыгранном
агрессивном действии — один размер по правилу, «до» с вложенным, шаг 0.1 BB:

| Действие | Размер «до» |
|---|---|
| открытие, не `SB` | 2.0 BB (`OPEN_BB`) |
| открытие с `SB` | 3.0 BB (`OPEN_SB_BB`) |
| изоляция лимпа | 3.0 BB + 1 BB за лимпера; из `BB` — 4.0 BB |
| 3-бет в позиции / без позиции | 3 × / 4 × открытие |
| 4-бет | 2.2 × 3-бет |
| 5-бет | олл-ин |

Размер выше 40% эффективного стека (`COMMIT_SHARE`) — олл-ин. Эффективный стек не больше
своего, поэтому размер не меньше стека с вложенным (короткий стек) сливается тем же правилом.
На сыгранном узле размер — фактический из кадра, правило не применяется. Размер, названный
советником, — всегда размер одного из действий дерева, и у этого действия есть EV.

Ответ (ключи camelCase):

- `action` — действие с наибольшим `evUsd`, равенство — к пассивному; `sizeBb` — его `toBb`, у
  `fold` и `check` ключа нет; `spot`, `heroHand`, `effectiveStackBb`;
- `line` — восстановленная линия до решения героя, с прошлыми действиями героя и фолдами
  (у фолда нет `toBb`);
- `actions` — все действия героя на узле: `toBb` (кроме `fold`/`check`), `evUsd` и `evBb` — EV
  от решения героя до конца раздачи, стеком после раздачи; фолд (у `BB` против лимпа — чек) —
  опорная точка разницы;
- `bountyUsd` — сколько из разницы лучшего действия с опорным (фолдом, у `BB` против лимпа —
  чеком) дают головы, только в PKO;
- `ranges.hero.byAction` — равновесная стратегия героя на узле по классам (нулевые опущены, шаг
  0.01); `handFreq` — частоты класса его руки; после хода героя его диапазон на флоп —
  `byAction[action]`;
- `ranges.opponents[]` — участники дерева в раздаче, кроме героя: `role` (`opener`, `3bettor`,
  `4bettor`, `limper`, `shover`, `responder` — ещё не ходил), `reach` — частота класса, с которой
  равновесный соперник сыграл линию, `reachPct`, `stackBb`;
- `nash` — эксплуатируемость и итерации каждого решения (`icm` в долларах, `chip` в BB).

Пометки `preflop` — все пометки `pushfold` из таблицы выше в том же смысле, кроме
`close_spot`, плюс:

| Пометка | Что значит |
|---|---|
| `close_spot` | `evUsd` двух лучших действий героя равны с точностью допуска: решение на грани, разница мала |
| `fixed_sizing` | размеры несыгранных агрессивных действий — по правилу, а не по выбору |
| `postflop_checkdown` | в дереве есть колл без олл-ина, он разыгран вскрытием без ставок: колл слабых рук переоценён, позиция не учтена |
| `deep_stack` | эффективный стек больше `CHECKDOWN_TRUST_BB = 40`: вскрытию без ставок доверять меньше |
| `no_hero_limp` | герой на `SB` в споте `open`: лимп ему не предложен — допущение модели, замером не проверено |
| `limper_range_profile` | диапазон лимпера — из профиля по VPIP, а не из равновесия |
| `line_deviates` | действие героя в кадрах не то, что советовал последний ответ советника в `history` (`preflop` или `pushfold`): разбор идёт по фактической линии |

Бюджет (`tests/test_advice_budget.py`): `open` героя `UTG` на 25 BB у всех — 6-max ~0.8 с
при бюджете 2 с, 9-max ~1.8 с при бюджете 4 с. Глубокий стек 9-max — 40 BB ~2.7 с,
100 BB ~5.0 с: замер, без теста (журнал плана 5, Фаза 6).

Порог `PUSHFOLD_MAX_BB = 12` пока прежний: замер доли рейза в открытии на 6–20 BB —
`scripts/measure_pushfold_threshold.py` (запуск из `packages/poker-engine`), таблица — журнал
`docs/superpowers/state/2026-10-18-plan5-execution-notes.md`, раздел «Фаза 7»; смена константы —
по решению пользователя.

## Что ещё не сделано

Уровень T2 из спеки — сверка с публичными эталонами — есть только для HU push/fold по фишкам
(чарт HoldemResources, `tests/data/hu_nash_chart.json`); таблицы эквити и опубликованные
примеры ICM — впереди; у дерева префлопа публичного эталона с той же моделью нет, эталон — сведение
к push/fold. Постфлоп, мультипот и лимп героя первым в банк `advise` не советует. Модули `fgs` и `structure` не реализованы. `analyze`
советника не зовёт и по-прежнему ставит на префлопе пометку `no_pushfold`.
