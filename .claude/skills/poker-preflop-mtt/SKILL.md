# Префлоп MTT: push/fold

## Контракт

Действие, размер, EV и диапазоны допустимы **только** из ответа `poker-engine advise`. Нет
вызова — нет совета.

Запрещено:
- называть пуш, колл или фолд по памяти, по «чарту из головы» или по аналогии с другой рукой
- пересчитывать EV, проценты диапазона или ICM-поправку в уме
- подменять ICM-совет фишечным, когда они расходятся

Если вызвать движок невозможно, честно сказать «не посчитано» и разобрать спот качественно,
без действия и чисел.

## Как вызывать

Из корня репозитория:

```bash
packages/poker-engine/.venv/Scripts/poker-engine.exe advise --input hand.json
```

Вход — JSON `{context, nodes, history?}`: `context` и `nodes` — ровно форма `analyze`
(турнирный контекст и узлы решения по скриншотам, совет — на последнем), `history` — прошлые
ответы `advise` в этой раздаче, по порядку; можно не передавать. Вывод — одна строка JSON.
Битый вход — `{"error": "..."}` и код возврата 1.

Ответ `{"advisor": null, "notApplicable": [...]}` — не ошибка: спот не push/fold (рейз не в
олл-ин, мультипот, постфлоп, стек выше 12 BB первым в банк). Причину пересказать пользователю
и не советовать действие.

## Как читать ответ

- **Совет — ICM.** `action` (`allin` | `call` | `fold`) следует из `ev.icm.marginUsd > 0`:
  разница EV в долларах между активным действием и фолдом для точной комбинации героя против
  равновесия соперников. `sizeBb` — сколько герой ставит (при `fold` ключа нет).
- **Фишки — объяснение поправки.** `ev.chip.marginBb` и `ranges.hero.chipPct` — то же без
  денежной лесенки. Когда знаки `marginBb` и `marginUsd` расходятся, это и есть ICM-поправка:
  «по фишкам колл прибылен, но вылет стоит дороже удвоения». Совет всё равно — по ICM.
- **Головы — отдельно.** `ev.bountyUsd` — сколько из `marginUsd` дают головы PKO. Называть
  отдельной строкой: «без головы колл был бы минусовым». Голова есть, только если герой
  накрывает соперника.
- **Диапазоны.** `ranges.hero.icmPct` — доля всех рук, которыми герой играет активно в
  равновесии; `handFreqIcm` — как часто его класс рук. `ranges.opponents[]` — кто и чем
  пушит или коллирует (`classes`), это и есть «почему»: против какого диапазона колл.
- **`nash`** — точность решения: эксплуатируемость в долларах (`icm`) и в BB (`chip`).

Каждая пометка в `flags` — что сказать пользователю:

| Пометка | Что сказать |
|---|---|
| `mh_bias` | ICM по Malmuth-Harville: шанс большого стека на высокие места завышен, на баббле — оценка |
| `field_homogeneous` | игроки вне стола считаются одинаковыми по стеку: разброс поля не учтён |
| `pko` | турнир с головами: ICM-игра включает наличные за нокаут |
| `bubble_protection` | учтён возврат бай-ина на баббле: вылет до денег дешевле обычного |
| `ladder_incomplete` | лесенка выплат снята не целиком: призы за непокрытые места считаются нулевыми |
| `late_reg_open` | поздняя регистрация открыта: лесенка предварительна |
| `no_overcall` | модель не видит оверколлов: после первого колла остальные фолдят |
| `fold_as_walk` | фолд открывающего моделируется уходом банка к большому блайнду |
| `close_spot` | спот на грани: EV действий почти равны, ошибка здесь стоит мало |
| `nash_not_converged` | решение не сошлось до допуска: диапазоны и EV приблизительны |

## Чего советник не делает

- Не открывает рейзом, не делает 3-бет, рестил-пуш и не играет против лимпа — это этап 4.
- Не советует на постфлопе и в мультипоте: спот с двумя олл-инами перед героем — отказ.
- Не учитывает рост собственного ценника после нокаута — только наличные за голову.
- `analyze` советника не зовёт: на префлопе у него пометка `no_pushfold`.

## Связанные скиллы

- `poker-math` — пот-оддсы, ICM, PKO для спотов вне push/fold.
- `poker-ontology` — позиции, эффективный стек, стадии турнира.
