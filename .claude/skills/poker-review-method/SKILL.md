# Разбор раздачи по кадрам (L7)

Пользователь сыграл раздачу, перед каждым своим решением снял скриншот и теперь отдаёт их по
одному. На каждый кадр тренер даёт правильное действие с размером и «почему». Своё решение
пользователь не называет и сверяет в голове: отчёта «совпало / ошибка» нет.

Состояние разбора — **файл раздачи**, а не память модели: контекст, кадры как пришли, ответы
шагов, факты объяснения и итоги улиц. Модель ничего не считает — только переписывает экран
(`poker-hand-vision`, L6) и пишет текст из печати фактов.

## Контракт

- Действие, размер и каждое число ответа — **только** из `display` фактов `why` шагов файла.
  Числа нет в фактах — его нет и в ответе: фразу переписать без числа.
- Перед отправкой — `coach lint`. `{"ok": true}` — отправлять; `{"ok": false, "untraced": […]}` —
  чинить **текст**, а не факты и не файл раздачи, и прогнать линтер снова.
- Файл раздачи руками не править: только `coach start`, `step`, `undo`.

## Сессия

Из корня репозитория (`poker-engine` — `packages/poker-engine/.venv/Scripts/poker-engine.exe`):

```bash
poker-engine lobby find --title "Fifty Stack $5.50"                # файл турнира по названию
poker-engine coach start --hand hand.json --context "<файл турнира>" --late-reg open|closed
poker-engine coach step  --hand hand.json --frame frame.json       # на каждый кадр; '-' — stdin
poker-engine coach lint  --hand hand.json --text answer.md         # перед каждым ответом
poker-engine coach undo  --hand hand.json                          # «кадр прочитан неверно»
```

1. **Старт.** Файл турнира — по названию турнира из заголовка окна стола:
   `poker-engine lobby find --title "<название из заголовка стола>"` → `{"tournaments": [{"path",
   "start", "payoutsFinal"}, …]}`, по дате начала.
   - **Один файл** — `coach start --context <path> --late-reg open|closed`. Флаг — по панели
     стола **первого кадра** раздачи: «Поздняя регистрация» — `open`, «Ср. стек» — `closed`.
     Средний стек движок считает сам: после регистрации — из стартового стека и входов файла, во
     время неё — по столу кадра (пометка `field_from_table`). Файл турнира руками не править.
   - **Несколько** — спросить пользователя дату турнира и взять файл с этим `start`.
   - **Ни одного** — попросить кадры лобби (два захода, L6 «Контекст из лобби») и запустить
     `poker-engine lobby read`.

   `payoutsFinal: false` — второго захода не было: раздача разбирается на предварительных
   выплатах (пометка `payouts_provisional`). Файл раздачи новый на каждую раздачу: `start` не
   перезаписывает существующий.
2. **Каждый кадр:** L6 → кадр → `coach step`. Вывод — `{"step", "advisor", "answer", "why",
   "streets"}`. Ошибка `{"error": …}` — кадр прочитан неверно: по L6 перечитать поле, названное
   в тексте; файл не тронут.
3. **Текст** по фактам `why` этого шага (форма ниже) → `coach lint` → ответ пользователю.
4. **«Кадр прочитан неверно»** (говорит пользователь или видно по ошибке следующего шага) —
   `coach undo` снимает последний кадр, его шаг и итог улицы, которую он закрыл; затем `coach
   step` с исправленным кадром.

## Форма ответа

```
Шаг 1. 3-бет до 6.0 BB.

Почему:
- 3-бет лучше фолда на +$0.35 (по фишкам — +0.41 BB) и олл-ина на +$0.21.
- UTG1 — открывший, входит с 15.0% рук; 3-бет на CO — 9.8% твоего диапазона.
- Против этого диапазона AQs …

Допущения: колл тебе не предложен — в модели колл открытия только у закрывающего действие.
```

Один спот: герой на `CO` против открытия `UTG1`, первое решение раздачи. Числа примера — печать
фактов этого шага: `vsBaseUsd`, `vsBaseBb` (опорное — фолд), `vsSecondUsd` (второе — олл-ин),
`opponent.UTG1.role` и `.reachPct`, `heroRange.raise`, пометка `flag.no_cold_call`. Откуда что:

| Строка ответа | Факты |
|---|---|
| Заголовок | `action` (действие с размером); номер шага — `step` |
| Чем лучше | `baseAction`, `vsBaseUsd`, `vsBaseBb` (против опорного: фолда, у `BB` против лимпа — чека); `secondAction`, `vsSecondUsd`, `vsSecondBb` (против второго) |
| ICM-поправка | `chipBestAction` — лучшее по фишкам, когда оно другое; совет всё равно по ICM |
| Головы PKO | `bountyUsd` |
| Диапазон героя | `heroReachPct` — что соперник видит у героя после его линии; `heroRange.<действие>` — доля диапазона героя на каждое действие; `heroHandFreq.<действие>` — рука смешанная |
| Соперники | `opponent.<позиция>.role` — роль словом (`открывший`, `3-беттор`, `лимпер`…), `.stackBb`, `.reachPct` |
| Стек и банк | `effectiveStackBb`, `potBb`, `toCallBb`, `requiredEquity` (пот-оддсы колла) |
| Линия | `line` |
| Допущения | `flag.<пометка>` — что сказать, по таблице пометок `poker-preflop-mtt` |

У `pushfold`: `marginUsd`, `marginBb` вместо разниц, `heroIcmPct`, `heroChipPct`,
`heroHandFreqIcm`, `heroHandFreqChip`, `opponent.<позиция>.icmPct`, `.chipPct`.

## Правила разбора

- **Линия героя = линия тренера.** Пользователь останавливает разбор на первом расхождении,
  поэтому прошлые ответы — собственная линия героя: «ты открылся», «твой 3-бет». Движок уже
  учёл их (`history`), диапазон героя по линии — `heroReachPct`.
- **`line_deviates`** — герой сыграл не то, что советовал прошлый ответ. Сказать прямо («на
  прошлом шаге совет был другим — разбираю по линии, как она сыграна») и разбирать по факту.
- **Не спрашивать**, что сделал пользователь, и **не сравнивать** с его решением.
- **Отказ** (`advisor: null`) — пересказать причину из фактов `reason.<советник>`; действия не
  называть и не подбирать «по смыслу».
- **Кадр флопа и дальше** — «постфлоп тренер пока не разбирает» (без номера этапа: линтер
  считает его числом) и итог префлопа из фактов шага, закрывшего
  улицу: `preflop.line`, `preflop.<позиция>.role`, `.stackBb`, `.reachPct` — какой диапазон
  каждый принёс на флоп. Итога нет — `preflop.reason`, пересказать.
- **Пометки** — каждая пометка ответа одной фразой в «Допущениях», по таблице `poker-preflop-mtt`.
- **Второе действие совпадает с опорным** (`secondAction` — тот же фолд, что `baseAction`) —
  одна фраза: «лучше фолда на …»; второй раз фолд не называть.
- **Олл-инщик** — `opponent.<позиция>.stackBb` у него `0.0 BB`: стек ушёл в банк. Стек не
  называть; размер олл-ина — из `line` или `toCallBb`.

## Что линтер считает числом

След — числа из `display` фактов всех шагов файла и номера шагов `1..N`. Числа текста
сравниваются строкой:

- **Печать — как есть:** `2.0 BB`, а не `2 BB`; `15.0%`, а не `15%` — тренер переписывает,
  а не округляет. Знак можно опустить (`0.35 BB` из `+0.35 BB`); запятая читается как точка,
  но писать — точкой, как в печати.
- **Единица — знаком:** `%`, `BB`, `$`; не «процентов», не «бб» словом.
- **Не числа:** позиция с цифрой — `UTG1`, `UTG+1`; `3-бет`, `4-bet`, `8-max` — через дефис
  (`3bet`, `8max` — числа); записи рук — `77`, `A5s`, `T9o`, `98s`, `A5`, `AhKd`.
- **Рука — старшей картой вперёд:** `A5s`, `98s`, `K9`; `5A`, `89s`, `9T` — числа.
- **Пара рядом с единицей — число:** `77 BB`, `77%`, `$77` — числа; `BB 77` — позиция и рука.
  Фразу «77 BB коллирует» переписать: «BB коллирует с 77».
- **Обратные кавычки** линтер пропускает целиком — только для имён и слов пользователя (номер
  места из его текста, ник), **не** чтобы спрятать число: `` `3.5 BB` `` — нарушение правила,
  даже если линтер его пропустил.

## Связанные скиллы

- `poker-hand-vision` — кадр со скриншота, съёмка лобби для `lobby read`; что делать с ошибкой
  `coach step` и `lobby read`.
- `poker-preflop-mtt` — как читать ответ советника и таблица пометок.
- `poker-ontology` — позиции, улицы, словарь линий.
- `poker-math` — числа вне разбора по кадрам.
