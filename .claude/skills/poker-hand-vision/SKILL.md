# Кадр и контекст со скриншота (L6)

Скилл переписывает экран в JSON, который читает движок: **кадр** стола — для `coach step`,
**контекст** турнира из лобби — для `coach start`. Сессию разбора ведёт `poker-review-method`
(L7); словарь — `poker-ontology`.

## Контракт

- **Только видимое.** Поле, которого нет на экране, не угадывается: ни карты соперника, ни
  стек под всплывающим окном, ни «наверное, сфолдил». Нет обязательного поля — один точный вопрос
  пользователю («сколько фишек у места справа от кнопки?»), не список.
- **Никакой арифметики.** Фишки переписываются фишками (`unit: "chips"`, поля `*Chips`), банк —
  как показан: в BB движок переводит сам, делит на `blinds.bb` без округления. Не делить на
  блайнд, не складывать ставки с банком, не вычитать вложенное из стека.
- **Подгонять числа под валидатор запрещено.** Ошибка `coach step` — это сигнал, что кадр
  прочитан неверно, а не что число надо подвинуть. Поле, названное в ошибке, перечитать на
  скриншоте; не видно или не сходится — спросить пользователя.

## Кадр стола

Один скриншот — один кадр, сделанный перед решением героя. Форма — узел `analyze` плюс
`unit` и банк «середина». Единицы в одном кадре одни: `*Chips` вместе с `*Bb` — отказ.

| Поле | Где на экране | Заметки |
|---|---|---|
| `street` | число карт на столе: 0 — `preflop`, 3 — `flop`, 4 — `turn`, 5 — `river` | |
| `unit` | как показаны стеки: фишки — `"chips"`, BB — `"bb"` (по умолчанию) | |
| `blinds` | заголовок окна стола или лобби: `{"sb", "bb", "ante"}` в фишках | в фишках обязателен `bb > 0` |
| `level` | заголовок окна стола, номер уровня | необязательно |
| `heroRank`, `playersLeft` | счётчик места в турнире («90 / 496»): место героя и сколько осталось | |
| `buttonSeat` | номер места с фишкой дилера `D` | |
| `heroCards` | две карты героя: ранг и масть, `"Jh"`, `"Th"` | |
| `board` | общие карты по порядку выкладки | на префлопе `[]` |
| `potChips` / `potBb` | надпись банка, **если** она — полный банк: середина плюс ставки улицы | |
| `potCenterChips` / `potCenterBb` | надпись банка, **если** она — только середина без ставок улицы | ровно один из двух банков |
| `toCallChips` / `toCallBb` | кнопка колла героя («Call 1,400») | нет колла (чек) — `0` |
| `raiseToChips` / `raiseToBb` | кнопка рейза, если видна | необязательно |

Место — объект в `seats`, одно на каждое занятое место за столом:

| Поле | Где на экране | Заметки |
|---|---|---|
| `seatIndex` | своя нумерация мест: по ходу игры (по часовой), одно место — один номер во всех кадрах раздачи | позиции движок считает от кнопки по возрастанию номера |
| `name` | ник под аватаром | |
| `stackChips` / `stackBb` | число под ником: что осталось за столом | олл-ин — `0` |
| `investedChips` / `investedBb` | фишки перед местом **на этой улице** | на новой улице — с нуля |
| `inHand` | есть ли карты рубашкой (или открытые) у места | сфолдил — `false` |
| `isHero` | место героя | ровно одно |
| `vpip`, `vpipHands` | бейдж статистики, если клиент его показывает | необязательно |
| `bountyUsd` | ценник головы над местом в PKO, как показан | не делить пополам |

Пустое место (никто не сидит) в `seats` не пишется. Мест не больше `seatsPerTable` контекста.

## Контекст из лобби

| Поле | Где на экране |
|---|---|
| `payouts` | вкладка выплат: `[{"from", "to", "amount"}]` — места и приз за место |
| `placesPaid` | сколько мест платят |
| `entrants` | входов всего (с ре-энтри) |
| `playersLeft` | осталось игроков |
| `lateRegOpen` | открыта ли поздняя регистрация |
| `seatsPerTable` | размер стола: 6-max — `6`, 8-max — `8` |
| `averageStackChips` / `averageStackBb` | средний стек из лобби; фишками — как показан, движок поделит на `bb` кадра |
| `bubbleRefundUsd` | возврат бай-ина на баббле, если турнир его даёт; необязательно |

## Ошибка `coach step`

Ответ `{"error": "…"}` с кодом 1 — кадр отвергнут, файл раздачи не тронут. Текст называет поле
или место: «стек на месте 5 вырос внутри раздачи», «мест за столом (7) больше, чем
seatsPerTable (6)», «в кадре два банка», «поле stackBb не для кадра в chips». Перечитать
**только** названное, исправить кадр и повторить `coach step`. Если на скриншоте поле читается
так же — спросить пользователя, а не менять число. Кадр уже прошёл, но прочитан неверно —
`coach undo`, затем `coach step` с исправленным кадром.

## Проверить на приёмке

Особенности клиента GG, которых без скриншотов пользователя не знает никто; до приёмки (Фаза 14
плана 6) это параметры кадра, а не допущения:

- что показывает надпись банка — полный банк или только середину (`pot*` против `potCenter*`);
- в чём показаны стеки — фишки или BB (переключатель клиента), и где виден большой блайнд;
- есть ли бейдж VPIP и сколько рук за ним;
- как выглядит олл-ин, стек 0 и место, которое вышло из раздачи;
- где на экране ценник головы в PKO и средний стек в лобби.

## Связанные скиллы

- `poker-review-method` — сессия разбора: куда идёт кадр и что делать с ответом.
- `poker-ontology` — позиции, улицы, эффективный стек.
